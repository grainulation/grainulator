# Remove Grainulator without losing research

Use the channel that owns the exact installed copy: remove a local npm consumer dependency from that consumer, remove a source checkout only when it contains no needed work, or uninstall the selected plugin through its host. For a published Homebrew installation use Homebrew. Removing one copy does not remove other copies or refresh a running host.

Before removing a launcher that is registered with a host, explicitly detach or rebind that owned registration. Preserve wrappers, permissions and unrelated hooks. Native enrolled hook/checker copies and their required gate are deliberately independent of package-manager cleanup; use the explicit enrollment handoff procedure rather than deleting them.

Tool-only removal retains project `claims.json`, `compilation.json`, research sessions, evidence packets, exports and `.grainulator` state. User memory defaults to `~/.grainulator/memory`; fetch cache defaults to `~/.grainulator/cache/smart-fetch`. `GRAINULATOR_MEMORY_DIR`, `GRAINULATOR_FETCH_CACHE_DIR` and explicit path options can select custom locations. Inspect those locations before any optional data cleanup; they may contain unrelated data.

The native-host workspace binding defaults to `~/.config/grainulator/workspace.json`, with `GRAINULATOR_CONFIG` and `GRAINULATOR_WORKSPACE` overrides. It is separate from host-owned settings. Native assets live under the explicit runtime installation/enrollment paths reported by local runtime diagnostics. Keep migration sources, receipts and backups until the rollback window closes.

No package uninstall, upgrade, doctor or demo operation purges user data. There is no general purge command. Never delete all agent caches or a bound workspace as a troubleshooting step. Share only reviewed diagnostic output; diagnostics do not upload a support bundle.
